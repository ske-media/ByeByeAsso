# Modèle de menaces — Kroov

Phase 10 · 28 octobre 2026. Chaque menace du prompt maître (§18) est reliée à la mitigation **dans le code** et au **test automatisé** qui la vérifie. Les tests cités s'exécutent dans la CI (`tests/security` par API directe contre un serveur réel, `tests/integration` sur PostgreSQL, `tests/e2e` Playwright).

## Acteurs et surfaces

| Acteur                           | Surface                                                                                           | Confiance                                      |
| -------------------------------- | ------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| Public anonyme                   | pages `/[orgSlug]/*`, `/api/v1/public/*`, `/l/{token}`, `/desinscription/*`, `/paiement/*` (fake) | aucune ; limitation de débit, jetons dérivés   |
| Acheteur / adhérent / bénévole   | liens signés (jeton dérivé HMAC, haché en base), ou compte connecté                               | le jeton **est** l'autorisation ; 404 uniforme |

| Prestataire de paiement / e-mail | `/api/v1/payments/webhooks/{provider}`, `/api/v1/email/webhooks/{provider}`                       | signature sur le corps brut, idempotence       |
| Worker                           | base de données, files pg-boss                                                                    | acteur `system`, scoppé par organisation       |
| Opérateur                        | `/api/v1/health`, `/api/v1/metrics`                                                               | métriques : jeton Bearer, aucune donnée perso  |

## Hypothèses et limites assumées

- Le reverse proxy (ou l'hébergeur) termine TLS, pose `x-forwarded-for` et n'est joignable que par lui : `TRUST_PROXY=true` **uniquement** dans ce cas, sinon tout le trafic anonyme partage un même compteur de débit (`direct`).
- La CSP tolère `'unsafe-inline'` (App Router sans nonce). Évolution notée : nonce par requête via `proxy.ts`.
- Pas de WAF ni de protection anti-bot : la limitation de débit protège contre l'abus simple, pas contre une attaque distribuée — à déléguer à l'hébergeur / CDN.
- Les sessions ne sont plus mises en cache dans un cookie (phase 10) : une révocation est immédiate, au prix d'une requête indexée par appel.
- Le chiffrement au repos et la haute disponibilité de PostgreSQL sont délégués à l'hébergeur de la base.
